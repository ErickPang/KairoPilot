# 当前工作台结构

## 组织与执行

项目与任务是持久化单元。任务保存模型、策略、目录、模板、计划、引用和草稿。运行引擎中的 AgentConfig 是内部执行配置，不提供独立人格管理或会话隔离功能。

主进程通过显式 IPC 合同提供能力；渲染进程只使用 preload 桥接。主任务共用执行锁，只读子调查按父任务策略与额度执行。取消、授权拒绝、失败、暂停分别记录状态；待授权操作不会因切换任务而执行。

启动先设置数据根目录并取得单实例锁，再安装应用生命周期钩子。未取得锁的进程直接退出，不初始化凭证、编辑器或任务数据库。取得锁的启动过程记录执行状态是否已经初始化；初始化失败仅清理已就绪的执行资源，不再次打开故障数据库。非交互启动期清理失败记录脱敏原因后仍退出，避免保留不可用实例；启动期间的退出请求会取消后续窗口创建。

正常退出仍按“确认草稿保存 → 停止执行 → 退出”顺序进行。保存请求具有唯一 ID 和窗口身份，主进程在最多 15 秒内每 250 ms 重发同一请求，覆盖 React 尚未挂载时的消息丢失；渲染进程对同一 ID 只保存一次，迟到回复不能解除新请求的界面锁。响应只传递保存状态及固定原因码，不传递草稿正文或原始错误。`[Shutdown]` 日志区分 `draft`、`communication` 和 `cleanup` 阶段并脱敏。正常运行中的保存、通信或清理失败均保留应用供重试，不能借启动期策略跳过真实未保存输入。

草稿串行写入队列同时追踪在途操作。只有内容匹配且队列已清空才认定保存完成；撤回输入时会校正防抖保存状态，避免已落盘却持续显示“保存中”，也避免旧快照匹配掩盖尚未完成的新写入。

## 配置、规则与数据

配置文件 kairopilot.json 的当前版本为 4.2.0，workbench 为 2，包含模型服务、工作台默认值、外观、技能插件来源和联网配置。全局 AGENTS.md 位于数据根目录，项目规则位于授权目录。内置要求、用户输入、规则、技能方法、背景记忆分别装配；规则不能授予权限。

chatDb.ts 直接创建 schema 7 的完整表、索引和触发器，不运行版本升级。启动按必需列名校验，不依赖列顺序；仅额外允许同版本遗留的 `sessions.binding_id` 和 `projects.rules`，保留原数据而不使用这些字段。缺少必需列、存在未知列、缺少索引/触发器或版本不符仍拒绝启动。数据库持久化任务、运行、工具、审批、成果、草稿、队列、记忆、辅助用量及项目授权。不建立新的项目与人格绑定表，不自动覆盖、转换或删除其他数据目录。

API Key 使用异步 safeStorage。`loadKairoPilotConfigFromDiskAsync` 在启动时解密并缓存凭证，不写文件；普通同步配置读取只使用已装配的进程内凭证。保存新的模型/搜索密钥先等待异步加密，再读取最新配置并同步原子保存，避免异步等待期间覆盖其他配置更新。`shouldReEncrypt` 为真时准备新的密文；其余情况复用 `safe-storage:v1:` 密文。解密失败不进入配置初始化/保存步骤。独立进程读取其他配置目录也必须使用异步读取入口。配置原子保存与普通故障备份仍保留，它们是当前格式的写入保护，不是历史格式转换。

## 代码与验收入口

插件分为三部分：`PluginPackageManager` 校验和保存声明式安装包，`ConnectionManager` 管理任务绑定的 MCP 生命周期，`PluginManager` 作为现有管理与工具发现接口的门面。安装包自身不运行代码；MCP 协议使用官方 SDK，工具动作仍进入已有工具网关。包内技能通过 `pluginSkills.ts` 索引，生命周期归属安装包。原 Worker/Node VM 执行器已移除，旧插件只保留阻止状态和原文件。

连接绑定任务、包哈希、工作目录及权限指纹，工具目录须独立批准。停用、更新、任务设置/权限变更、项目撤权、删除任务及退出应用均撤销相关连接。连接、批准和可选 Bearer Token 不落盘，不在应用重启时自动恢复。`runtimeSupervisor.ts` 负责 stdio 进程归属、最小环境变量与终止；它不提供操作系统隔离。远程服务与可信本地程序的权限边界见[插件文档](plugins.md)。

- src/main/bootstrap/appBootstrap.ts：启动与生命周期。
- src/main/store/configNormalization.ts：当前配置规范化；configRepository.ts：读取、原子保存和首次规则初始化。
- src/main/core/llm/provider.ts：模型工厂与能力查询；utils.ts：唯一的提供商辅助函数实现。
- src/main/store/chatDb.ts：当前数据库结构。
- scripts/p0-electron-smoke.mjs：统一验收入口，支持默认原生验收、--ui-polish 和显式真实模型验收。
- scripts/unified-workbench-entry.ts：新数据目录验收及重启验收，复用任务计划、记忆、委派、技能插件、授权、队列和 UI 测试。

验证命令：npm run verify、npx vite build、npm run smoke:native。原生验收使用隔离目录和本地合成模型，不发送真实项目资料。真实模型验收需要显式选择，不默认调用。

原生验收另包含真实 bootstrap 的启动失败、初始化期间退出和双 Electron 进程场景：第二进程退出后，第一进程的运行状态必须保持不变；第一进程正常退出时仍须完成草稿确认与运行回收。

可用 `npm run smoke:native -- --bootstrap-only` 单独运行这些场景；其中正常退出对草稿写入添加延迟，确认请求重发不重复写入，且未发送输入在退出前真实保存。
