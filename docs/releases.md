# GitHub 封板与手动分发

当前应用版本为 0.2.0。封板提交、版本号与标签应由维护者确认后创建；本地修复或构建不代表已经提交、打标签或上传 Release。

## 封板前检查

1. 将产品源码、必要回归测试、CI 和原生验收脚本纳入同一个候选提交；不提交用户配置、密钥、安装缓存、日志和测试产物。
2. 在 Node.js 24+ 环境从干净 checkout 执行 `npm ci`、`npm run verify`、`npm run smoke:native`。原生验收使用临时目录和本机协议夹具，不发送项目资料。
3. 执行 `npm run build` 生成安装包（配置禁止自动发布）。只做模块构建用 `npx vite build`；需要指定打包目标时先构建模块，再显式执行 `npx electron-builder --publish never`。
4. 根据经过验收的平台和架构创建安装包，文件名包含版本、系统和架构。首次可只分发一个已验收目标，不把构建配置中的目标列表当作跨平台实测结果。
5. 在干净测试用户环境验证首次启动、模型密钥保存、普通对话、工具审批、拒绝/停止、退出重启及数据保留。至少使用目标模型的合成任务验证，不上传真实项目文件。
6. 检查包内容、版本、SHA-256、许可证与说明；确认后才上传 GitHub Release。推荐首次勾选 Pre-release，说明已知限制及反馈入口。

## 运行环境与兼容范围

- Electron 45.2.1；better-sqlite3 13.0.3 使用随 npm 包分发的 N-API 预构建文件，打包不再按 Electron ABI 重编译。数据库仍为当前 schema 7，不加入历史数据迁移。
- 开发/CI 使用 Node.js 24+ 和 npm 10+；Vite 7.3.7、Vitest 5.0.5、electron-builder 26.18.0。版本锁定由 package-lock.json 保存。
- 如 Electron 官方二进制下载在当地不可达，可在安装时显式设置 `ELECTRON_MIRROR`；安装器仍使用官方 npm 包内的校验值验证下载。不要跳过完整性校验。
- 应用不提供操作系统级 Shell 沙箱。执行权限、目录白名单和审批是应用层限制。
- 不支持的旧配置或数据库会明确停止启动，原文件不会自动转换、清空或删除。客户使用历史版本数据前需保留备份并核实格式兼容性。
- 模型与搜索服务由客户配置，网络、Token 用量及第三方可用性取决于相应服务。单元测试和本机协议夹具不代替每个提供商的真实兼容测试。

## 下载、安装与更新

客户从当前仓库的 GitHub Releases 下载与系统和架构匹配的完整安装包。首版不进行后台检查、下载或自动安装更新；新版本仍从 Releases 手动下载安装。升级前退出应用并备份数据目录，首次升级需验证新旧版本的数据格式兼容性。

未签名/未公证的 macOS 包可能被系统阻止启动。Release 应如实说明签名状态；不要要求客户全局关闭系统安全保护。签名/公证不是代码封板的前提，但影响安装体验。Windows 与 Linux 同样只列出经过验证的产物。

## 数据与隐私

默认本地数据目录为 `~/.kairopilot`。配置密钥使用系统安全存储能力加密；安装包需验证当前系统可用性。GitHub 下载不包含客户数据。

剪贴板建议默认关闭，客户可在常规设置开启；只有应用聚焦且开启时读取本地剪贴板。建议不会自动发送给模型。

错误上报默认未启用。配置 DSN 后也只允许发送版本、环境、时间、级别和脱敏异常条目，不保留自由文本、堆栈、请求、用户字段或面包屑。对话和项目资料是否发送给模型取决于客户发起的任务与已授予的权限。
